Study conditions and limits

  • Each case used one model sample per method. Graph and exact-flat received byte-identical prompts in all eight cases.
  • Each case’s complete graph closure set the five capped methods’ shared evidence allowance. Full context received the complete corpus.
  • Every method used the same Hydra-assisted refresh and currentness executor. Standalone vector safety and graph-engine superiority are outside the comparison’s scope.
  • Provider input exposure includes uncached input, cache writes and cache reads. The primary ratio excludes the canonical no-op (M08).

Verify offline

Use Python 3.10 or later. The bundle includes both verifier scripts and all reconstruction inputs.

  1. Download the evidence ZIP and SHA-256 file. Match them with shasum -a 256 -c on macOS or sha256sum -c on Linux, followed by the checksum filename.
  2. Extract the ZIP, open a terminal in the extracted folder and run python3 scripts/verify_public_evidence.py

The verifier checks file hashes and independently recalculates report values from 4,681 source rows. It traces receipts and reconciles provider accounting across 48 cells and 152 saved model-study payloads. Its scope is the saved observation. Live model replication, provider attestation and HydraDB replay require separate evidence.
