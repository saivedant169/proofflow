# Checked CSV report handoff

An imported CSV workspace can download its two current net revenue reports as `proofflow-current-reports.txt`. The file contains the company and selected-region amounts, the report and claim artifact IDs, and the UTC time when the server checked both reports. It is a static snapshot. A later correction can supersede the file, which never updates itself. The file does not contain raw CSV rows, session credentials, source IDs, or a share link.

`POST /api/import/export` takes `{ "generation": "…", "report_ids": { "company": "…", "region": "…" } }` from the visible workspace. Within the existing session lock, the server matches the import generation and both report heads, then uses native HydraDB evidence to check that the reports and both revenue claims are current and complete. The route returns a JSON envelope `{filename, media_type, checked_at, content}`; the browser downloads the server’s UTF-8 text. Success and error responses use `Cache-Control: no-store`. The export neither recalculates revenue nor writes artifacts, receipts, or graph data. An incomplete import, head mismatch, or stale or unknown evidence refuses the snapshot. An unavailable evidence backend also returns no file. On a failure the browser reconciles with the server; if reconciliation fails, it withholds current figures until a state reload succeeds.

Imported USD cents are JSON integers within JavaScript’s safe range and base-10 strings outside it. Currency display and file formatting preserve exact cents in both cases. Historical values stay labeled as such; the original saved evidence and receipts retain their canonical contents.

On 2026-11-15, all **9 local Chromium workflows** passed against the built frontend and real HydraDB OSS on loopback, with 0 retries, skips, flakes, unexpected results, or runner errors. Playwright used one worker on macOS arm64. The runs exercised desktop Chromium and targeted checks at 390×844 and 320×844. Results below use authored functional fixtures.
